## 1. 概述

本次改动包含两个主题：
- **岗位投递优先级**：AI 在推荐岗位时标注优先级标签（主攻/并行/看见就投等），侧边栏和推荐卡片同步显示
- **布局适配**：岗位详情从全屏浮层改为容器内报告卡片；移动端和网页端分别适配容器宽度；侧边栏宽度适配手机屏幕

## 2. 数据模型变更

### 2.1 JobMatch 新增 `priority` 字段

```typescript
// lib/types.ts
export interface JobMatch {
  title: string
  match: number          // 0-100
  priority?: string      // 新增：AI 给出的优先级标签，如 "主攻方向"、"并行准备"、"看见就投"、"长期关注"
  reasons: string[]
  gaps: string[]
}
```

- `priority` 为可选字符串，由 AI 在 Step 8 推荐岗位时填写
- AI 可根据用户情况灵活命名，不限定枚举值
- 常见标签示例：主攻方向、并行准备、看见就投、长期关注、紧急补强后可投
- 前端不按 `match` 百分比自动计算优先级；以 AI 给出的 `priority` 为准
- 当 `priority` 为空时，前端不显示优先级徽章

## 3. Prompt 变更

### 3.1 `lib/prompts.ts` — showResults 工具说明

在 `showResults` 工具说明中补充 `priority` 字段：

```
jobMatches 中每项需包含 priority 字段（字符串），根据用户情况给出投递优先级标签：
- "主攻方向"：匹配度高、用户能力强、行业前景好，应集中精力主攻
- "并行准备"：值得投递但需补一些能力，可作为第二志愿并行准备
- "看见就投"：匹配度尚可，碰到合适机会就投，不用花太多精力准备
- "长期关注"：目前差距较大但方向有价值，列入长期关注清单
- 你也可以根据用户情况自创更贴切的标签

**确定优先级时必须综合考虑以下维度**（不能只看匹配度百分比）：
1. **匹配度**：用户能力与岗位要求的契合程度
2. **市场供需**：该岗位的招聘规模、竞争激烈程度、地域分布（岗位少但匹配高 → 不宜主攻）
3. **用户基础**：用户当前能力与岗位的差距大小，补足成本
4. **行业前景**：该方向 3-5 年的增长趋势

priority 用自然语言灵活表达，让用户一眼看懂你的推荐力度。不要用数字或固定枚举。
```

## 4. UI 变更

### 4.1 JobMatchCard — 推荐卡片加优先级徽章

**文件**: `components/JobMatchCard.tsx`

- 卡片标题行左侧新增优先级徽章（如 `priority` 有值）
- 徽章样式：小圆角标签，颜色柔和，与匹配度百分比并排显示
- 当 `priority` 为空时不渲染徽章

### 4.2 Sidebar — 岗位列表加优先级

**文件**: `components/Sidebar.tsx`

- 每个岗位项标题上方新增优先级徽章（紧凑尺寸）
- 徽章样式与 JobMatchCard 保持一致
- 移动端侧边栏宽度适配：当前 `w-[260px]` 在小屏手机（320px 宽）上过大，改为 `w-[min(260px,80vw)]`

### 4.3 JobDetail — 重写为纯报告卡片

**文件**: `components/JobDetail.tsx`

**重大改动**：从带输入框的聊天窗口改为纯阅读型报告卡片。

#### 交互行为
- 打开后自动发送一次请求到 `/api/chat`，prompt 中要求 AI 按 6 大模块输出岗位分析报告
- AI 流式返回内容，以 markdown 格式实时渲染
- **无输入框**，无追问功能，用户阅读完后点"返回"回到主对话
- 如需追问，用户回到主对话中提问

#### 6 大报告模块
1. **📖 岗位概述** — 这个岗位是做什么的、在哪些行业、典型公司
2. **💼 日常工作** — 典型的一天、主要产出、协作关系
3. **⭐ 你需要突出的能力** — 结合用户测评数据，面试/简历中应强调哪些
4. **🛤️ 准备路径** — 入行前要补什么、学习资源、项目建议
5. **📊 能力差距分析** — 用户当前能力 vs 岗位要求，差距按优先级排列
6. **🚀 下一步行动** — 3-5 条具体可执行的行动建议

#### 布局
- 容器内显示（`absolute inset-0` 在 `max-w-lg/max-w-2xl` 容器内），非 `fixed inset-0`
- 顶部栏：返回按钮 + 岗位名 + 优先级徽章 + 匹配度
- 内容区：可滚动 markdown 渲染
- 底部：无输入框，仅有"返回主对话"按钮

#### 加载态
- 打开时显示加载动画（"正在生成岗位分析报告..."），流式内容逐步展示

### 4.4 容器宽度适配

**文件**: `app/page.tsx`

- 当前主容器：`max-w-lg`（448px）
- **移动端**：保持 `max-w-lg`，适配手机屏幕
- **网页端**：改为 `max-w-2xl`（672px），适中阅读宽度

实现方式：使用 Tailwind 响应式断点
```html
<div class="max-w-lg md:max-w-2xl mx-auto ...">
```

- `max-w-lg`：默认（手机，< 768px 屏幕）
- `md:max-w-2xl`：中等屏幕及以上（≥ 768px，平板/桌面）

## 6. 兼容性

- `priority` 为可选字段，旧数据（无 priority）正常显示，只是不显示优先级徽章
- JobDetail 重写不依赖 localStorage 或云端数据结构变更
- 布局变更仅涉及 Tailwind class，不影响功能逻辑
